# GPT 家族史 · 语言的回声（V3）

> 事情开始于时间线上的一条视频。最后真正留下来的，却大多发生在时间线之外。

这是我发在抖音上的《GPT 家族史》V3 的可编辑源码。它从文字与记忆讲到图灵、Transformer、GPT 和 ChatGPT，也记录了我第一次比较完整地经历**发现、判断、纠偏、交付**的过程。

如果你是从评论区过来的，这里能找到创作经过、实际技术实现，以及本地渲染方法。这个版本并不完美，但它终于没有一直留在工程文件夹里。

| 项目 | V3 工程 |
| --- | --- |
| 形式 | 代码绘制的短片；中英字幕，无旁白 |
| 时间轴 | 18 个场景，150 秒，30 fps，共 4,500 帧 |
| 画幅 | 1920 × 1080，16:9 |
| 最终实现 | Node.js / CommonJS、`@napi-rs/canvas`、Python、FFmpeg |
| 公开内容 | 渲染源码、场景配置、分镜、字幕、四幅原画、配乐合成源码与复现说明 |
| 许可 | 代码使用 [MIT](LICENSE)；图片、音乐、字体的权利边界见下文 |

这里公开的是制作工程，不包含成片视频、音乐或字体二进制。Blender 和 Remotion 出现在前期试错中；**本仓库恢复的 V3 最终工程使用 Canvas 逐帧绘制，不依赖 Remotion，也不调用模型 API。**

## 时间线之外

*以下根据我在 2026 年 9 月 28 日写下的同名作者手记整理。模型名称、迭代经历和“破万赞”均保留手记中的个人叙述，不是模型评测或实时平台统计。*

### 既然没人做，那我就自己做

事情开始得很偶然。那天我刷到一条用 Claude Opus 5.5 做的视频，印象里才三百多赞，音乐模板也几乎没有人在用。但我看完以后，记住了它。

不只是因为画面有多炫，而是它让我觉得，AI 的历史也可以不被写成一张参数表。模型、语言、历史、人，可以被放进同一个故事里。

那一刻我觉得：这个形式会火。后来，那条视频从几百赞涨到几千，再到破万，模板下面也陆续出现了不同版本。但我一直是 GPT 用户，又没有看到一个自己觉得足够完整的 GPT 版本。所以我想：**既然没人做，那我就自己做。**

### AI 可以高效地，把错误的方向执行到底

一开始，我把参考片交给 GPT-6 Sol，以为接下来只剩等待。它却开始搭 Blender、做场景、调灯光，把“电影感”理解成一个越来越庞大的 CG 工程。技术复杂度不断上升，成片离我想要的东西越来越远。

后来我去翻原作者的评论区，发现核心路线是 AI 生图加 Remotion，于是重新调整：先生成关键画面，再用 Remotion、TypeScript 做动画、排版和转场。

这一版接近了很多，但新的问题也来了：**它太像 PPT 了。** 每一帧单独看都不算难看，视频却几乎只有背景缓慢放大、文字出现，再换下一张。画面越来越精致，运动却越来越像模板。

接下来几天，最折磨人的不是完全做不出来，而是每一版都像“快到了”。这里修好了，另一个地方又坏了；粒子越来越多，却很难回答这些粒子为什么要出现。

我怀疑过模型、提示词，也怀疑过上下文。重新开任务，只留下参考片和目标，让 Astra Ultra 从头做，结果仍然不尽人意。直到第三天早上，我把踩过的坑、已经确认的方向和之前的讨论重新整理了一遍，再开一个新任务，才有了后来真正发出去的版本。

### 不完美，但终于交付了

发布时，我知道它还有闪帧、画面不稳定、逻辑和事实错误，转场也只能说能用。美术之间没有真正形成贯穿全片的视觉母题。如果重做，很多地方我都会改。

但那时已经改了太多遍，最后还是发了。随后点赞、收藏和评论不断上涨，有人问提示词，有人问源码，也有人认真讨论里面的技术、视觉和 AI 感。它就这么破万赞了。

**我比任何人都清楚，这条片离我脑子里的那个版本还差得很远。** 如果提前知道会有这么多人看到，我一定会再认真修一轮。可如果坚持必须做到 95 分才发布，等我终于满意，那个窗口也可能已经过去。

这并不意味着“随便做个 80 分，赶紧发就行”。恰恰相反，最大的遗憾是机会真的来到以后，才发现自己本来还能准备得更好。比“完美还是速度”更重要的，可能是更早开始，把判断、试错和迟早要踩的坑，尽量留在机会出现以前。

### Prompt 不是魔法

最开始，我以为 AI 足够强以后，人的工作只是把需求描述清楚。后来才发现，描述只是开始。

AI 很快就能给出一个“看起来像答案”的东西。真正困难的是：**你还能不能判断，它有没有真的答到问题。** 有时候不是画面丑，而是镜头根本没动；不是特效不够，而是特效没有叙事意义。

到后续新版的讨论中，提示词已经接近施工图：哪个手印先消失，粒子怎么变化，镜头怎么运动，哪条线先连向哪个词。可换一个模型，结果仍然不同。当要求已经足够明确，剩下的就是模型、工具和工程本身真实存在的边界。

这次真正留下来的，不只是“学会让 AI 做视频”，而是走完了**发现、判断、纠偏、交付**这条路。AI 正在让答案变得更容易获得，可什么值得被问、什么答案值得相信、什么事情值得真正做出来，这些问题又回到了我们这里。

## V3 实际是怎么做出来的

创作过程里尝试过几条路线，开源时应以留下来的源码为准。V3 的工作方式是：把每一个时间点的画面算出来，交给 Canvas 绘制，再把像素送给 FFmpeg 编码。

```text
story.json：场景、起止时间、中英字幕
                    ↓
render.cjs：按时间定位场景，计算动画与转场
                    ↓
三个 motif 模块 + 四幅原画 + 字体
                    ↓
Canvas 逐帧绘制 → RGBA 像素流 → FFmpeg / H.264
                    ↓
Python 调度三段渲染 → 拼接 → 可选封装配乐
```

### 时间轴、动画与字幕

- **时间轴驱动画面。** [story.json](v3/story.json) 中的 18 个场景连续覆盖 0–150 秒，保存场景标识、主题、原画名称和字幕区间。[render.cjs](v3/render.cjs) 根据绝对时间选择场景，再换算成场景内时间。尺寸在入口中固定为 1920 × 1080，单改 JSON 的尺寸字段不会改变画布。
- **运动由代码计算。** 字符逐个出现，路径沿采样点展开，节点、连线和粒子按时间移动；位置、透明度和转场使用插值及缓动控制。Canvas 的裁剪、渐变、蒙版与合成操作负责局部显隐和多模态场景的过渡。
- **绘制职责分开。** [film_motifs.cjs](v3/film_motifs.cjs) 承担开场对话、续写、反馈、家谱等主要动态场景；[ink_motifs.cjs](v3/ink_motifs.cjs) 绘制注意力、词元和推理等意象；[language_motifs.cjs](v3/language_motifs.cjs) 提供工具等语言意象。它们是可检查的绘图函数，不是模型实时推理结果。
- **字幕在渲染时画入视频。** 中英文字来自场景配置，按时间区间淡入淡出。仓库另附[双语 SRT](v3/output/GPT家族史_双语字幕.srt)，便于查看或单独使用；渲染入口直接读取 JSON，并不从 SRT 反向生成字幕。

### 从像素到视频

片段渲染在每个帧时间点绘制 Canvas，读取 RGBA 像素，通过标准输入送入 FFmpeg，以 `libx264` 编码，输出 `yuv420p` 格式的 H.264 视频。代码会在写入管道受阻时等待排空，避免不受控制地继续堆积帧数据。低分辨率片段仍先在 1080p 画布上绘制，再缩放输出。

[render_all.py](v3/render_all.py) 将全片分为 **0–50、50–100、100–150 秒**三段，最多并行运行两个 Node 进程，然后拼接视频并封装 AAC 音频。这个拆分有利于分段排查，也限制同时运行的渲染进程数；它不代表已经测得完整渲染耗时或峰值内存。

| 工具 | 在本工程中的用途 |
| --- | --- |
| Node.js / CommonJS | 渲染入口与绘图模块 |
| `@napi-rs/canvas` `0.1.100` | 字体、图像、路径、文字和逐帧像素绘制；版本由锁文件固定 |
| Python 3 | 调度片段、拼接与可选音频合成 |
| FFmpeg / ffprobe | 视频编码、拼接、音频封装与媒体检查 |
| NumPy / SciPy（可选） | 保留的程序化配乐合成与处理源码 |

## 后续方向：《问题的另一边》

**这是尚未完成的新版构想，不属于本仓库已经实现的 V3 功能。**

视频发出去以后，我想的逐渐不再是“怎么把 GPT 家族史做得更漂亮”，而是“我到底真正想讲什么”。后来，新主题定成了《问题的另一边》。真正吸引我的，不只是一个个型号依次出现，而是问题本身的位置一直在变化。

我想让图灵的 `CAN MACHINES THINK?` 被拆成词元，进入机器，最后收束为 `THE MACHINE CAN ___`，预测出 `THINK`。它没有回答图灵，只是完成了一次 Next Token Prediction；两个相隔几十年的问题，却在那个画面里重叠了。

然后，**续写，变成了对话。** 来自教室、办公室、实验室和卧室的问题不断汇聚，形成语言洪流，再坍缩为一个闪烁的光标。对话框从两边展开，最后把问题交回给人：**你想创造什么？**

在 9 月 28 日的手记中，前 55 秒的剧本、镜头和部分动画路径已经讨论得很细，但继续逐镜头返工的成本太高，新版因此暂时停下。这些设想保留在这里，作为下一次创作的方向，不作为已完成的演示承诺。

## 安装与环境

准备 Node.js（2026-10-07 验证为 26.8.1）、Python 3（2026-10-07 验证为 3.9.6）以及包含 `libx264` 的 FFmpeg / ffprobe，并让 `node`、`python3`、`ffmpeg`、`ffprobe` 在 PATH 中可用。上述是 2026-10-07 的实测版本，不代表已测试所有版本。克隆仓库并安装依赖：

```sh
git clone https://github.com/zeyu-notes-space/gpt-family-history.git
cd gpt-family-history
npm ci
```

配乐合成是可选步骤，建议在虚拟环境安装：

```sh
python3 -m venv .venv
# macOS / Linux
. .venv/bin/activate
python3 -m pip install -r v3/audio/requirements.txt
```

Windows 使用对应的虚拟环境激活命令；既有验证未覆盖 Windows。推荐预留至少 8 GB 内存及足够磁盘空间；原渲染编排最多同时启动两个 Node 进程，实际峰值内存尚未测量。

## 必须准备的字体

渲染入口按以下路径注册字体，别名分别为 `Chinese`、`Serif`、`SerifItalic`：

```text
fonts/NotoSerifCJKsc-Regular.otf
fonts/Serif.otf
fonts/SerifItalic.otf
```

请从有明确许可证的来源取得支持简体中文的字体、英文衬线正体和斜体，并放到上述路径。中文可采用对应名称的 Noto Serif CJK SC；英文可选择有明确授权的衬线字体，再按入口约定命名。保留各字体许可证，并自行检查其允许的使用和再分发范围；不要仅靠重命名判断格式或授权。

原包的中文字体条目损坏，英文字体及许可证未恢复，因此仓库不附带字体二进制。入口没有强制检查字体注册成功：字体缺失时可能继续运行，但会出现缺字、错误回退和版式差异。生成文件不等于正确复现；请先检查代表静帧。

## 静帧与关键片段

在仓库根目录执行：

```sh
# 每个场景生成一张代表静帧，共 18 张
npm run stills

# 指定时间，单位秒
node --expose-gc v3/render.cjs stills 3,8,14,20,29,40,47,57,65,75,85,95,105,115,125,134,143,149

# 多模态过渡：3 秒、640×360、无声
node --expose-gc v3/render.cjs segment 79 82 v3/output/sample-omni.mp4 640

# 家谱片段：1 秒、原生 1080p、无声
node --expose-gc v3/render.cjs segment 119 120 v3/output/sample-family.mp4
```

静帧写入 `v3/output/qa_stills/`。先运行静帧命令创建输出目录，再运行片段命令。片段参数依次为模式、起止秒数、输出路径和可选宽度；高度为宽度的 9/16。请使用得到偶数高度的宽度，例如 640、1280、1920，满足 yuv420p 编码要求。

## 完整渲染

### 使用自己有权使用的配乐

仓库不包含原包音乐。将有合法使用权的音频准备为 `v3/audio/soundtrack_150s.wav`（建议 150 秒、48 kHz、立体声），完成字体配置后执行：

```sh
npm run render
```

`v3/render_all.py` 调用 Node 分别渲染 0–50、50–100、100–150 秒，两个进程并行，接着用 FFmpeg 拼接视频并封装 AAC 配乐。产物为：

```text
v3/output/GPT家族史_语言的回声_1080p.mp4
```

必须在开始前准备音乐。原脚本是在三段视频渲染结束后才检查配乐是否存在，缺失时会报错，但已生成的分段仍在输出目录。

### 无音乐版本

如不添加音乐，可先分别生成三段，再拼接为无声视频：

```sh
npm run stills
node --expose-gc v3/render.cjs segment 0 50 v3/output/segment_000.mp4
node --expose-gc v3/render.cjs segment 50 100 v3/output/segment_050.mp4
node --expose-gc v3/render.cjs segment 100 150 v3/output/segment_100.mp4
python3 -c "from pathlib import Path; Path('v3/output/silent-concat.txt').write_text(\"file 'segment_000.mp4'\nfile 'segment_050.mp4'\nfile 'segment_100.mp4'\n\")"
ffmpeg -hide_banner -y -f concat -safe 0 -i v3/output/silent-concat.txt -c:v copy -an -movflags +faststart v3/output/gpt-family-history-silent.mp4
```

### 可选：程序化配乐源码

`v3/audio/compose_score.py` 以固定随机种子合成钢琴、弦乐、拨弦与空气音色，没有外部音频读取；`render_audio.py` 做母带处理和音频 QA。可运行：

```sh
python3 v3/audio/render_audio.py
```

这会生成新的音频文件及测量记录。原包文档称其为原创程序化配乐，但发布者说明影片音乐来自抖音；两者来源描述存在冲突，因此原包 WAV 一律排除，不用原文档的“原创”标签作为其授权证明。保留的仅是可检查的合成源码，使用者可选择不使用。2026-10-07 对此合成流程仅完成语法检查，没有执行完整音频生成或音频 QA。
